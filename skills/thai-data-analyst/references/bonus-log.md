# Bonus / Points Log Reference
## ไฟล์: "bonus.xlsx"
## ใช้กับ shwe666 / ubet89 / 88fed

log การจ่าย point/โบนัส **รายธุรกรรม**

> ⚠️ บอทไม่ได้เก็บทุกแถว — ตอน parse จะ **สรุปเป็นรายวัน** ก่อนเก็บ
> 1 แถวที่เก็บ = 1 คู่ (วันที่ × ประเภท point) ไฟล์ดิบยังอยู่บนดิสก์ตาม
> retention ปกติ 6 เดือน

---

## Columns ในไฟล์ดิบ

| Column | คำอธิบายภาษาไทย |
|--------|-----------------|
| **AddTime** | เวลาที่จ่าย point ← ใช้เป็นวันที่ของรายการ |
| **Type** | ประเภท point เช่น `Loyalty Point`, `Referrer Reward Point` |
| **Username** | บัญชีที่ได้รับ |
| **Lv** | level ของ member ตอนได้รับ (ส่วนใหญ่ว่าง) |
| **Points** | จำนวน point ที่จ่าย — **เป็นค่าที่ถูกย่อสเกลไว้ ห้ามอ่านตรงๆ** (ดูหัวข้อถัดไป) |
| **Memo** | เหตุผล/หมายเหตุ เช่น `Loyalty Point ( Period No : 98 )` |

## ⚠️ สเกลของคอลัมน์ `Points` (จุดที่พลาดกันบ่อยที่สุด)

คอลัมน์ `Points` ในไฟล์ point log **ไม่ได้ใช้สเกลเดียวกับคอลัมน์เงินอื่นในระบบ**

| | คอลัมน์เงินทั่วไป (BIn, R, Bonus, ...) | คอลัมน์ `Points` ในไฟล์นี้ |
|---|---|---|
| สเกลในไฟล์ | ตัด 3 ศูนย์ (÷ 1,000) | ย่อไว้ 100 เท่า (SH666) |
| config | `scaleFactor` | `pointsScaleFactor` |

**ตัวอย่าง** (SH666, `reward_point.xlsx` เดือน 2026-07):

```
แถว "Money Daily" ค่าดิบในไฟล์ = 1.200
  → 1.200 × 100        = 120 MMK
  → 120 × 0.787 (fxRate) = 94.44 บาท
```

ถ้าอ่านค่าดิบตรงๆ จะได้ "1.2" ซึ่งผิดจากความจริง **100 เท่า** —
อาการที่เคยเจอคือรายงานว่า "Loyalty Point รวม 278.8" ทั้งที่ของจริงคือ 27,880 MMK

สเกลนี้ใช้เหมือนกันกับ **ทุก `Type`** ในคอลัมน์ (Loyalty Point, Loyalty Point Claim,
Cashback Point, Auto Cashback Point, Money Daily / Weekly / Monthly, Reward Point,
ผู้เข้าร่วมกิจกรรมผู้ชนะประจำวัน ฯลฯ) — ไม่ต้องแยกสเกลตามประเภท

### ⏳ ค่านี้ยังไม่ถือว่าปิดจ๊อบ

`pointsScaleFactor = 100` มาจากการยืนยันด้วยปากเปล่าของผู้ใช้ **ยังไม่ได้เทียบกับ
ภาพหน้าจอ Power BI จริง** และค่านี้เคยเปลี่ยนไปมาแล้วหลายรอบ (เคยเป็น 100,000
มาก่อนหน้านี้) — ถือเป็นคำตอบที่ดีที่สุดที่มีตอนนี้ ยังไม่ใช่ข้อสรุป

**วิธีปิดจ๊อบ:** เปิดไฟล์ `reward_point.xlsx` ของ SH666 เดือนใดก็ได้ หาแถวที่รู้ยอดจริง
(เช่น Money Daily) แล้วเทียบยอดรวมของ `Type` นั้นกับตัวเลขเดียวกันในหน้า Power BI
อัตราส่วนที่ได้คือค่าที่ถูก — แก้ที่ `config/site-aliases.json` จุดเดียว

### เว็บที่ยังไม่ได้ตั้งค่า

U89 / 88F **ยังไม่มีหลักฐาน** ว่าใช้สเกลเท่าไร (หรือมีไฟล์ point log ของตัวเองไหม)
จึงจงใจไม่ตั้งค่าไว้ — และเมื่อค่าของ SH666 เองยังไม่นิ่ง ยิ่งไม่ควรก๊อปไปใช้ต่อ

ถ้ามีไฟล์ point log ของเว็บที่ยังไม่ได้ตั้งค่าเข้ามา บอทจะ **error ทันทีตอน parse**
พร้อมข้อความ "ยังไม่ได้ตั้งค่า pointsScaleFactor สำหรับเว็บนี้" — ตั้งใจให้พังเสียงดัง
ดีกว่าเดาสเกลของ SH666 มาใช้แล้วรายงานตัวเลขผิดแบบเงียบๆ

> วิธีแก้: เปิดไฟล์จริงของเว็บนั้น เทียบค่าดิบกับยอดที่รู้ว่าถูก แล้วเพิ่ม
> `pointsScaleFactor` ของเว็บนั้นใน `config/site-aliases.json`
> (ที่เดียวกับ `scaleFactor` / `fxRate` — single source of truth)

## Columns หลังสรุปรายวัน (ที่บอทเก็บจริง)

| Column | ความหมาย |
|--------|----------|
| **Date** | วันที่ (จาก `AddTime`) |
| **Type** | ประเภท point |
| **total_points** | ผลรวม **ค่าดิบ** ตามที่อยู่ในไฟล์ — ใช้ cross-check กับ Power BI เท่านั้น **ห้ามรายงานเป็นจำนวนเงิน** |
| **total_points_THB** | ต้นทุน point จริงเป็นเงินบาท = `total_points × pointsScaleFactor × fxRate` — **ตัวนี้คือตัวที่ใช้ตอบคำถาม** |
| **transaction_count** | จำนวนครั้งที่จ่าย |

> `total_points_THB` แปลงมาให้เรียบร้อยแล้ว **ห้ามคูณสเกลหรือ fxRate ซ้ำอีก**
> (กฎเดียวกับ `_THB` ของไฟล์อื่น)

## Metric หลักที่ควรพูดถึงเวลามีคนถาม

1. **ต้นทุน point รวมต่อวัน** — `total_points_THB` รวมทุก `Type`
   ควรดูคู่กับ `R_THB` ใน Daily Value ว่าจ่าย point เพิ่มแล้วรายได้ขึ้นตามไหม
   (ทั้งคู่เป็นบาทแล้ว เทียบกันได้ตรงๆ)
2. **ประเภทไหนกินงบมากสุด** — เทียบ `total_points_THB` ข้าม `Type`
   `Referrer Reward Point` ที่โตเร็วผิดปกติเป็นธงแดง referral abuse
   (ดู `fraud-anomaly-detection.md`)
3. **จ่ายถี่แต่ทีละน้อย หรือจ่ายก้อนใหญ่** — `total_points_THB / transaction_count`
   ค่าเฉลี่ยต่อครั้งที่กระโดดผิดปกติควรตรวจสอบ
4. **เทียบกับ `other transfer.xlsx`** — ไฟล์นั้นเก็บ manual credit ที่พนักงาน
   เติมให้ ส่วนไฟล์นี้เป็น point ตามระบบ ถ้าจะดูต้นทุนรวมที่ให้ลูกค้าต้องดูทั้งคู่

> คำอธิบายประเภท point แต่ละแบบอยู่ใน `casino-metrics.md` หัวข้อ
> "ประเภท Point ต่างๆ ใน reward point.xlsx / other transfer.xlsx"
