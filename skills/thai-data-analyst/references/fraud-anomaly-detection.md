# Fraud & Anomaly Detection Reference
## ใช้กับ shwe666 / ubet89 / 88fed — ตรวจจับ pattern ที่อาจเกี่ยวข้องกับการโกงของพนักงาน/ลูกค้า

> ⚠️ **หลักการสำคัญ**: สิ่งที่ตรวจเจอในหัวข้อนี้คือ "สัญญาณผิดปกติที่ควรสืบสวนต่อ" ไม่ใช่ "ข้อสรุปว่ามีการโกงแน่นอน" — ต้องรายงานเป็นระดับความน่าสงสัย (สูง/กลาง/ต่ำ) พร้อมเหตุผล ห้ามฟันธงว่าใครโกงจากข้อมูลเชิงสถิติเพียงอย่างเดียว เพราะอาจมีคำอธิบายที่ไม่ใช่การโกงได้เสมอ (เช่น ลูกค้าจริงที่นิสัยการเล่นแปลก, error ของระบบ tracking)

---

## Case 1: Referrer ผิดปกติ (Referral Fraud)

### 1.1 Referrer มี downline เยอะผิดปกติ
**ไฟล์ที่ใช้**: `referrer.xlsx` (คอลัมน์ Total Mems, Total BIn Mems, BIn Mems%)

**วิธีตรวจ**:
- หา Total Mems ของแต่ละ referrer แล้วเทียบกับ percentile 95 ของ referrer ทั้งหมด — คนที่สูงกว่านั้นผิดปกติ
- ดู **BIn Mems%** (สัดส่วนคนที่ referrer พามาแล้วฝากเงินจริง) — ถ้า referrer มี Total Mems เยอะมากแต่ BIn Mems% ต่ำมาก (<1%) แปลว่าพามาเยอะแต่คุณภาพต่ำมาก น่าสงสัยว่าเป็นบัญชีปลอม/farming ไม่ใช่ลูกค้าจริง
- ⚠️ พบในข้อมูลจริงแล้ว: บาง AD/Agent มี **BIn Mems% เกิน 100%** (เช่น 196%, 725%) ซึ่งเป็นไปไม่ได้ในทางตรรกะปกติ (คนฝากมากกว่าคนที่มาทั้งหมด) — เป็น data anomaly ที่ควรสืบสวนทันที อาจเกิดจาก tracking ผิดพลาดหรือคนเดียวสมัครหลาย username ผ่าน link เดียวกัน

### 1.2 Referrer ที่ตัวเองไม่เล่น/ไม่ฝาก แต่ downline สร้างรายได้ให้เยอะ (เคสที่ user ยกตัวอย่าง)
**ไฟล์ที่ใช้**: `Member Referrer Detail.xlsx` (BIn, R, BIn Days ต่อ downline แต่ละคน) + `vip.xlsx`/`member list.xlsx` (เช็คว่า referrer เองมี BIn/BIn Days เท่าไหร่) + `reward point.xlsx` (Referrer Reward Point ที่จ่ายให้ referrer)

**วิธีตรวจ**:
1. หา username ที่ปรากฏเป็น "Referrer" ใน `Member Referrer Detail.xlsx` บ่อยๆ (มี downline เยอะ)
2. เช็คตัวเอง (username นั้น) ใน `vip.xlsx`/`member list.xlsx` — ถ้า **BIn = 0 หรือ BIn Days = 0 หรือน้อยมาก** (ไม่เคยเล่น/ฝากเงินตัวเอง) แต่มี Referrer Reward Point สะสมสูงต่อเนื่องใน `reward point.xlsx`
3. **ธงแดง**: referrer ที่ตัวเองไม่ active เลย แต่รับ Referrer Reward Point เป็นประจำทุก Period — เพราะ Referrer Reward Point ควรมาจากการที่มีคนแนะนำเข้ามาเล่นจริง ถ้า referrer ไม่เล่นเองเลยและรับ point ต่อเนื่อง อาจเป็น:
   - พนักงานสร้างบัญชี referrer ปลอมเพื่อดูดค่าคอมมิชชั่น
   - Referrer สร้างบัญชีลูกหลายบัญชี (self-referral) เพื่อปั่นยอด

### 1.3 Downline ไม่มีการเล่น/ฝากเลย แต่ยังนับเป็นสมาชิกที่ referrer ได้ผลตอบแทน
**วิธีตรวจ**: ใน `Member Referrer Detail.xlsx` ดู downline ที่ `BIn = 0` และ `BIn Days = 0` (บัญชีว่างเปล่า ไม่เคยฝากเลย) — ถ้า referrer คนหนึ่งมีสัดส่วน downline แบบนี้สูงผิดปกติ (เช่น >70% ของ downline ทั้งหมดไม่เคยฝาก) น่าสงสัยว่าเป็นการสมัครบัญชีปลอมจำนวนมากเพื่อ "ดัก" โบนัสแนะนำเพื่อน (ถ้าโปรโมชั่นแนะนำเพื่อนให้ credit ตอนสมัคร ไม่ต้องรอฝาก)

## Case 2: Manual Credit + ถอนเงินแบบหลบเลี่ยง (Structuring / เงินปั่น)

### 2.1 ได้ manual credit แต่ไม่ฝากเงินจริง แล้วถอนออก
**ไฟล์ที่ใช้**: `other transfer.xlsx` (Type=7, manual credit ทุกประเภทรวมทั้งของรางวัล/คืนยอดเสีย) + `vip.xlsx`/`member list.xlsx` (BIn, Bo คือยอดฝาก/ถอนจริง)

**วิธีตรวจ**:
1. หา username ที่ปรากฏใน `other transfer.xlsx` บ่อยครั้งและ/หรือยอดสะสมสูง
2. เทียบกับ `BIn` (ยอดฝากสะสม) ใน `vip.xlsx`/`member list.xlsx` ของ username เดียวกัน
3. **ธงแดง**: manual credit สะสมสูง **แต่ BIn (ยอดฝากจริง) ต่ำมากหรือเท่ากับ 0** ในขณะที่ **Bo (ยอดถอน) สูง** — แปลว่าเงินที่ถอนออกไปส่วนใหญ่มาจาก credit ที่พนักงานเติมให้ ไม่ใช่เงินที่ลูกค้าฝากเข้ามาเอง ควรเช็ค memo ใน `other transfer.xlsx` ว่าเหตุผลที่ให้ credit สมเหตุสมผลกับพฤติกรรมจริงไหม (เช่น อ้างว่าเป็นรางวัลกิจกรรม แต่ไม่มีหลักฐานอื่นสนับสนุน)
4. เคสหนักสุด: username ที่ **ไม่มีประวัติ BIn เลยตั้งแต่สมัคร** (`First BIn` เป็นค่าว่างใน `member list.xlsx`) แต่มี manual credit + Bo สูง — บัญชีนี้อาจถูกสร้างขึ้นมาเพื่อรับเงินโดยเฉพาะ (mule account)

### 2.2 ถอนเงินทีละน้อยหลายครั้ง (Structuring)
**ไฟล์ที่ใช้**: `vip.xlsx`/`member list.xlsx` (BIn Counts, BIn Days, Med. BIn — ใช้เป็น proxy เพราะไม่มีไฟล์ transaction ระดับ Bo แยกครั้ง)

**วิธีตรวจ** (โดย proxy เนื่องจากไม่มีไฟล์ Bo แยกรายครั้งเหมือน BIn):
- ดู **Med. BIn** (median ยอดฝากต่อครั้ง) ที่ต่ำผิดปกติเทียบกับ **BIn Counts** ที่สูงมาก — ถ้าคนหนึ่งฝากถี่มาก (BIn Counts สูง) แต่แต่ละครั้งจำนวนเงินน้อยมาก (Med. BIn ต่ำ) ทั้งที่ BIn รวมสะสมสูง อาจเป็นการพยายามหลีกเลี่ยงเกณฑ์ตรวจสอบธุรกรรมขนาดใหญ่ (structuring/smurfing)
- **ข้อจำกัด**: การตรวจ pattern นี้ให้แม่นยำ ต้องมีไฟล์ transaction log ระดับรายการ (วันเวลา + จำนวนเงินแต่ละครั้ง) ซึ่งปัจจุบันไม่มีในชุดไฟล์ที่ได้รับ — ถ้าต้องการตรวจละเอียดขึ้น ควรขอไฟล์ deposit/withdrawal transaction log แยกจากทีม

## Case อื่นๆ ที่ตรวจได้จากข้อมูลที่มี

### 3. Bonus/Promotion Abuse
**ไฟล์**: `Promotion List.xlsx`
- โปรที่ **Pass% สูงผิดปกติ** (เช่น 90-100%) ทั้งที่เงื่อนไข (Pro Type = Bet/Bet Rate) ควรจะผ่านยาก — อาจมีคนรู้ช่องโหว่เงื่อนไขโปรนั้นแล้วเล่นเอาเปรียบเป็นกลุ่ม (bonus hunting/abuse) โดยเฉพาะถ้า Pro R ติดลบมากผิดปกติเทียบกับโปรประเภทเดียวกัน
- Member ที่เข้าร่วมโปรเดิมซ้ำๆ หลายรอบติดกัน (ต้องดูจาก `Pro (1st Day).xlsx` หรือ `Pro Records`/`Promotion List` ประกอบ) — โปรที่ควรได้แค่ครั้งเดียว (เช่น welcome bonus) แต่มีคนได้ซ้ำ

### 4. Agent/AD ที่มีผลตอบแทนติดลบผิดปกติ
**ไฟล์**: `AD Agent.xlsx` (สรุปรวม, มี R และ Total Mems)
- Agent ที่มี Total Mems น้อย (ลูกค้าไม่กี่คน) แต่ **R ติดลบเยอะผิดปกติ** เทียบกับ agent อื่นระดับเดียวกัน — อาจมีพนักงานที่ดูแล agent นั้นปั่น manual adjustment ให้ลูกค้าตัวเอง/พวกพ้องที่มาจากช่องทางนั้นเป็นพิเศษ

### 5. VIP ที่ Dormant นานแต่ยัง Active ใน Promotion/Reward
**ไฟล์**: `vip.xlsx` (Last BIn 2 Y) + `reward point.xlsx` / `other transfer.xlsx`
- Username ที่ `Last BIn 2 Y` สูงมาก (ไม่ฝากเงินมานาน) แต่ยังปรากฏได้รับ Loyalty Point/Cashback/Manual credit อย่างต่อเนื่องในช่วงเวลาเดียวกัน — เพราะ Loyalty/Cashback ควรคำนวณจาก Turnover ที่เกิดขึ้นจริง ถ้าไม่มีการเล่น/ฝากแต่ยังได้ point ต่อเนื่อง เป็นไปได้ว่าเป็น error ของระบบ หรือมีคนตั้งค่าให้บัญชีนี้ได้ point แบบ manual

### 6. Referrer/Agent ชื่อคล้ายกันเป็นกลุ่ม (Self-referral / Fake network)
**ไฟล์**: `referrer.xlsx`, `Member Referrer Detail.xlsx`, `member list.xlsx` (คอลัมน์ Phone)
- Username ที่มีรูปแบบคล้ายกันมาก (เช่น เลขไล่กัน, คำนำหน้าเดียวกัน) refer กันเองเป็นเครือข่ายปิด และมี Phone number ที่คล้ายกัน/ใกล้เคียงกัน (เช่น เลขท้าย 4 ตัวต่อเนื่องกัน) — สัญญาณของกลุ่มบัญชีที่ควบคุมโดยคนเดียว/กลุ่มเดียว สร้างขึ้นมาเพื่อหมุนโปรโมชั่นหรือ referral bonus กันเอง

## วิธีนำเสนอผลตรวจสอบ (สำคัญ — อย่าลืม)

เมื่อเจอ pattern ผิดปกติ ให้รายงานตามโครงสร้างนี้เสมอ (ทั้งใน Full Report Mode และ Conversational Mode):

1. **สิ่งที่พบ**: ตัวเลข/pattern เฉพาะเจาะจง (username, ตัวเลข, ช่วงเวลา) — ห้ามพูดกว้างๆ
2. **ทำไมถึงน่าสงสัย**: อธิบายเหตุผลเชิงตรรกะว่าทำไม pattern นี้ผิดจากพฤติกรรมปกติ
3. **ระดับความน่าสงสัย**: สูง/กลาง/ต่ำ — พร้อมเหตุผลว่าทำไมถึงจัดระดับนี้
4. **คำอธิบายทางเลือกที่เป็นไปได้** (ที่ไม่ใช่การโกง): ต้องใส่เสมอเพื่อความ fair เช่น ลูกค้า VIP จริงที่เล่นน้อยลงชั่วคราว, ระบบ tracking ผิดพลาด
5. **ขั้นตอนถัดไปที่แนะนำ**: เช่น "ควรให้ทีมตรวจสอบ manual log ของพนักงานที่ดูแล agent นี้" — ไม่ใช่การตัดสินขั้นสุดท้าย

**ห้ามเด็ดขาด**: ระบุชื่อพนักงานหรือกล่าวหาบุคคลใดว่า "โกง" อย่างชี้ชัดจากข้อมูลเชิงสถิติเพียงอย่างเดียว ให้ใช้คำว่า "ควรตรวจสอบเพิ่มเติม" หรือ "เป็นสัญญาณที่ควรเฝ้าระวัง" เสมอ
