# Member Detail Reference
## ไฟล์: "Member_Detail.xlsx"
## ใช้กับ shwe666 / ubet89 / 88fed

รายชื่อ member ระดับรายคนพร้อมยอดสะสมและเกมที่เล่นบ่อยที่สุด เป็น **snapshot**
(ไม่มีคอลัมน์วันที่รายแถว) — ผูกกับเดือนที่อัปโหลด

---

## คำอธิบาย Columns

| Column | คำอธิบายภาษาไทย | หน่วย |
|--------|-----------------|-------|
| **Username** | ชื่อบัญชีของ member | — |
| **Referrer** | username ของคนที่ชวนเข้ามา (ว่าง = สมัครเอง) | — |
| **BIn** | ยอดฝากสะสม | THB (พัน) |
| **Pro** | ยอดโปรโมชั่นที่ได้รับสะสม | THB (พัน) |
| **R** | Revenue ที่ member คนนี้สร้างให้บริษัท | THB (พัน) |
| **BIn Days** | จำนวนวันที่มีการฝากเงิน | วัน |
| **BIn (Pro)%** | สัดส่วนยอดฝากที่มาพร้อมโปรโมชั่น | สัดส่วน (0-1) |
| **Last BIn Date** | วันที่ฝากเงินครั้งล่าสุด | date |
| **Prefer Game** | ค่ายเกม/ประเภทเกมที่เล่นบ่อยที่สุด เช่น `JILI_SLOT` | — |

> ⚠️ อย่าสับสนกับ `Vip.xlsx` — ไฟล์นั้นมี `Last BIn 2 Y` (จำนวน**วัน**ที่ห่างจาก
> เมื่อวาน) ส่วนไฟล์นี้มี `Last BIn Date` (เป็น**วันที่**จริง) และมี `Prefer Game`
> ซึ่ง `Vip.xlsx` ไม่มี

## Metric หลักที่ควรพูดถึงเวลามีคนถาม

1. **เกมไหนได้ลูกค้าคุณภาพ** — group ตาม `Prefer Game` แล้วเทียบ `R` เฉลี่ย
   และ `BIn` เฉลี่ยต่อคน ใช้ตอบว่าค่ายเกมไหนดึงลูกค้าที่ฝากหนัก
   (ใช้คู่กับ `brand-game-value.md` ที่มองจากฝั่งยอดเดิมพันแทน)
2. **member ที่กำลังจะหาย** — `Last BIn Date` ห่างจากวันนี้เกิน 7 วัน
   คือกลุ่มเสี่ยงหลุด สอดคล้องกับนิยาม Lost ใน `vip-members.md`
3. **พึ่งพาโปรมากแค่ไหน** — `BIn (Pro)%` สูงแปลว่าฝากเฉพาะตอนมีโปร
   ถ้าทั้งฐานสูงขึ้นเรื่อยๆ = คุณภาพ member แย่ลง
4. **โครงสร้าง referral** — group ตาม `Referrer` เพื่อดูว่าใครมี downline เยอะ
   แล้วไปตรวจต่อใน `Referrer.xlsx` / `fraud-anomaly-detection.md`
