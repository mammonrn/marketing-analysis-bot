# Deposit Detail Reference
## ไฟล์: "Detail (Last 6 Months).xlsx"
## ใช้กับ shwe666 / ubet89 / 88fed

log การฝากเงิน **รายธุรกรรม** ย้อนหลัง 6 เดือน (หลักแสนแถว)

> ⚠️ บอทไม่ได้เก็บทุกแถว — ตอน parse จะ **สรุปเป็นรายวัน** ก่อนเก็บ
> 1 แถวที่เก็บ = 1 คู่ (วันที่ × ช่องทางจ่ายเงิน) ไฟล์ดิบยังอยู่บนดิสก์ตาม
> retention ปกติ 6 เดือน ถ้าต้องการสรุปแบบอื่นสามารถ re-parse ได้

## Columns ในไฟล์ดิบ

| Column | คำอธิบายภาษาไทย |
|--------|-----------------|
| **Username** | บัญชีที่ทำรายการ |
| **Type** / **TypeName** | ประเภทรายการ เช่น `In` / `3rd Party` |
| **PayName** | ช่องทางจ่ายเงิน เช่น `k_pay`, `wave_money` (ว่าง = ฝากมือ/ช่องทางไม่ระบุ) |
| **AddTime** | เวลาที่ผู้เล่นเริ่มทำรายการ ← ใช้เป็นวันที่ของรายการ |
| **Confirm Time** | เวลาที่รายการถูกยืนยัน |
| **Duration (m)** | ระยะเวลาที่ใช้ยืนยัน | นาที |
| **Points** | จำนวนเงินของรายการ |
| **Status** | ผลลัพธ์ เช่น `success` |
| **Modifier**, **UserTrueName / UserAccount / UserBank (Info)**, **UserAccount / CompanyAccount (Manual Deposit)** | ข้อมูลบัญชีปลายทาง ใช้ตอนตรวจสอบรายการมือ |

## Columns หลังสรุปรายวัน (ที่บอทเก็บจริง)

| Column | ความหมาย |
|--------|----------|
| **Date** | วันที่ (จาก `AddTime`) |
| **PayName** | ช่องทางจ่ายเงิน |
| **total_count** | จำนวนรายการทั้งหมดของวันนั้นในช่องทางนั้น |
| **success_count** | จำนวนรายการที่สำเร็จ |
| **success_rate** | success_count / total_count (0-1) |
| **avg_duration_min** | เวลาเฉลี่ยที่ใช้ยืนยัน เฉพาะรายการที่สำเร็จ (นาที) |

> `avg_duration_min` นับเฉพาะรายการสำเร็จโดยตั้งใจ — รายการที่ล้มเหลวจะหยุด
> จับเวลาตอนไหนก็ได้ ถ้ารวมเข้ามาจะทำให้ค่าเฉลี่ยเพี้ยนโดยไม่ได้สะท้อนความเร็วจริง

## Metric หลักที่ควรพูดถึงเวลามีคนถาม

1. **ช่องทางไหนมีปัญหา** — `success_rate` ต่ำผิดปกติในช่องทางใดช่องทางหนึ่ง
   คือสัญญาณว่า payment gateway นั้นมีปัญหา ควรเทียบข้ามวันเพื่อดูว่าเป็น
   ปัญหาชั่วคราวหรือเรื้อรัง
2. **ฝากเงินช้าลงไหม** — `avg_duration_min` ที่ค่อยๆ สูงขึ้นแปลว่าผู้เล่นรอ
   นานขึ้น กระทบ conversion โดยตรง
3. **สัดส่วนการใช้ช่องทาง** — `total_count` เทียบกันข้าม `PayName`
   ถ้าช่องทางหลักล่ม ยอดฝากรวมทั้งเว็บจะตกทันที
4. **เชื่อมกับยอดฝาก** — จำนวนรายการที่นี่ควรสอดคล้องกับ `BIn Counts`
   ใน `Daily (Count).xlsx` (ดู `deposit-count-distribution.md`)
