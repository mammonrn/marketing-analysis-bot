## คำอธิบาย Columns

| Column | คำอธิบายภาษาไทย | หน่วย |
|--------|-----------------|-------|
| **AD / Agent** | ชื่อช่องทางโฆษณา หรือ agent (แถว `Company` = ยอดรวมของบริษัทเอง) | — |
| **Agent** | agent ย่อยภายใต้ AD นั้น (`Total` = รวมทุก agent) | — |
| **Total Mems** | จำนวน member ทั้งหมดที่มาจากช่องทางนี้ | คน |
| **Total BIn Mems** | จำนวน member ที่ฝากเงินจริง | คน |
| **BIn Mems%** | สัดส่วน member ที่ฝากจริง = Total BIn Mems / Total Mems | สัดส่วน (0-1) |
| **BIn** | ยอดฝากรวมของช่องทางนี้ | เงิน → ใช้คอลัมน์ `_THB` |
| **ARPPU** | ยอดฝากเฉลี่ยต่อ member ที่ฝากจริง = BIn / Total BIn Mems | เงิน → ใช้คอลัมน์ `_THB` |
| **BIn (Pro)%** | สัดส่วนยอดฝากที่มาพร้อมโปรโมชั่น | สัดส่วน (0-1) |
| **Pro** | ต้นทุนโปรโมชั่น | เงิน → ใช้คอลัมน์ `_THB` |
| **Bonus** | ต้นทุนโบนัส | เงิน → ใช้คอลัมน์ `_THB` |
| **R** | Revenue สุทธิของช่องทางนี้ | เงิน → ใช้คอลัมน์ `_THB` |
| **DAU** | Daily Active Users | คน |
| **CIn** | ยอดเดิมพันรวม | เงิน → ใช้คอลัมน์ `_THB` |
| **Pw** | Profit/Win ของบริษัท (ติดลบ = ผู้เล่นชนะ) | เงิน → ใช้คอลัมน์ `_THB` |

## Metric หลักที่ควรพูดถึงเวลามีคนถาม

1. **ช่องทางไหนคุ้มที่สุด** — ดู `R` เทียบกับ `Total Mems` และ `Pro + Bonus`
   ช่องทางที่ได้ member เยอะแต่ `R` ต่ำ = ได้ปริมาณแต่ไม่ได้คุณภาพ
2. **คุณภาพ member ต่อช่องทาง** — `BIn Mems%` คือตัวชี้วัดตรงที่สุด
   ถ้าต่ำผิดปกติแปลว่าได้คนสมัครแต่ไม่ฝากจริง (ดู `fraud-anomaly-detection.md`
   ประกอบ ถ้าต่ำมากผิดปกติอาจเป็นบัญชีปลอม)
3. **ARPPU** — เทียบข้ามช่องทางว่าช่องไหนได้ลูกค้าที่ฝากหนักกว่า
4. **ต้นทุนต่อ R** — `(Pro + Bonus) / R` ยิ่งสูงยิ่งกินกำไร

> ⚠️ แถว `Company / Total` เป็นยอดรวม อย่านับซ้ำกับแถวย่อยเวลารวมยอด
