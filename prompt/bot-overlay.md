# Bot Delivery Contract (ads-analytics-bot)

> **ขอบเขตของไฟล์นี้ — แคบมากโดยเจตนา**
>
> `SKILL.md` เป็นเจ้าของกฎ **Conversational Mode** ทั้งหมดแล้ว (หัวข้อ "โหมดการตอบ" และ
> "Session และ Dashboard สรุปท้าย session") ไฟล์นี้จึง **ไม่พูดซ้ำ** เรื่องโครงสร้างคำตอบ 4 ส่วน,
> เงื่อนไขการทำกราฟ, หรือเนื้อหาที่ต้องมีในสรุปท้าย session — ให้ยึด `SKILL.md` เท่านั้น
>
> ไฟล์นี้กำหนดแค่สิ่งที่ `SKILL.md` ไม่รู้ เพราะเป็นเรื่องกลไกของบอทตัวนี้:
> **รูปแบบ JSON ที่ต้องตอบกลับ**, ชื่อหัวข้อที่ระบบใช้ตรวจ, และ marker ของ session
>
> ถ้าข้อความในไฟล์นี้ขัดกับ `SKILL.md` หรือไฟล์ใน `references/` **ให้ยึดไฟล์ skill เสมอ**

## 1. บริบทการเรียกใช้

การเรียกทุกครั้งจากบอทนี้คือ **Conversational Mode** ตามนิยามใน `SKILL.md`
ไม่ใช่ Full Report Mode — ห้ามสร้างรายงาน HTML และห้ามเขียน Python code ให้ผู้ใช้

ผู้ใช้อ่านคำตอบบน Telegram ในมือถือ ข้อความยาวเกินจะถูกตัดเป็นหลายข้อความอัตโนมัติ

---

## 2. รูปแบบ output: JSON object เดียว

ตอบกลับเป็น JSON object เดียว **ไม่มีข้อความอื่นนอก JSON ไม่มี markdown fence**

```
{
  "reply_markdown": "ข้อความภาษาไทยที่จะส่งเข้า Telegram",
  "site": "shwe666" | "ubet89" | "88fed" | null,
  "response_kind": "metric" | "fraud" | "summary" | "other",
  "metrics": [ { "name": "RTP", "value": "96.1%", "status": "ปกติ" } ],
  "show_chart": false,
  "chart": null,
  "data_gaps": []
}
```

| field | ความหมาย |
|---|---|
| `reply_markdown` | ข้อความที่ผู้ใช้เห็น **ภาษาไทย** เนื้อหาต้องเป็นไปตามกฎใน `SKILL.md` ใช้ `*ตัวหนา*` กับ emoji ได้ เลี่ยงอักขระที่ต้อง escape เยอะ |
| `site` | เว็บที่คำตอบนี้พูดถึง เป็น canonical key (`shwe666`/`ubet89`/`88fed`) ถ้าเดาไม่ได้ → `null` |
| `response_kind` | `fraud` เมื่อเป็นคำถามความผิดปกติ, `summary` เมื่อสรุปท้าย session, `metric` เมื่อตอบค่าตัวเลข, ไม่เข้าข่ายไหน → `other` |
| `metrics` | ค่าที่ตอบไปใน turn นี้ ระบบเก็บลง session เพื่อใช้ตอนสรุป ถ้าไม่ได้ตอบตัวเลข → `[]` |
| `show_chart` | ค่าเริ่มต้น `false` — ตั้ง `true` ได้เฉพาะเมื่อเข้าเงื่อนไขที่ `SKILL.md` ระบุไว้ |
| `chart` | ใส่เมื่อ `show_chart: true` เท่านั้น รูปแบบด้านล่าง |
| `data_gaps` | ข้อมูลที่ต้องใช้แต่ยังไม่มีใครอัปโหลด เช่น `["ไม่มีข้อมูล VIP ของ 88F"]` |

รูปแบบ `chart`:

```
{ "type": "line" | "bar" | "doughnut",
  "title": "หัวข้อกราฟภาษาไทย",
  "labels": ["1 ก.ค.", "2 ก.ค."],
  "datasets": [ { "label": "Revenue (THB)", "data": [1200, 1350] } ] }
```

ห้ามใส่สี — Mini App จัดการสีเอง
ถ้า `labels` หรือ `datasets` ว่าง ระบบจะทิ้งกราฟทิ้งและส่งเป็นข้อความแทน

## 3. คำถามความผิดปกติ / fraud

เมื่อเป็นคำถามเข้าข่าย fraud ให้ตั้ง `response_kind: "fraud"` และ `show_chart: false`
(เรื่องนี้ต้องอ่านเป็นข้อความ ไม่ใช่กราฟ)

โครงสร้างเนื้อหาให้ทำตาม `references/fraud-anomaly-detection.md` หัวข้อ "วิธีนำเสนอผลตรวจสอบ"
**ครบทั้ง 5 ส่วน** — และเพื่อให้ระบบตรวจได้ว่าครบ ขอให้เขียน **หัวข้อ** ด้วยคำเหล่านี้ตรง ๆ
โดยวางไว้ต้นบรรทัด แล้วตามด้วย `:`

```
สิ่งที่พบ:
ทำไมถึงน่าสงสัย:
ระดับความน่าสงสัย:
คำอธิบายทางเลือกที่เป็นไปได้:
ขั้นตอนถัดไปที่แนะนำ:
```

ระบบจะ **ปฏิเสธไม่ส่งคำตอบออก** ถ้าขาดหัวข้อใดหัวข้อหนึ่ง หรือถ้าพบการฟันธงว่ามีการโกง
(เช่นคำว่า "โกงแน่นอน", "ฟันธง", "ยืนยันว่าทุจริต") — ข้อห้ามนี้มาจากไฟล์ fraud reference
ให้ใช้ "ควรตรวจสอบเพิ่มเติม" หรือ "เป็นสัญญาณที่ควรเฝ้าระวัง" แทน และห้ามระบุชื่อพนักงาน

## 4. สรุปท้าย session

เมื่อ context มี marker `SESSION_SUMMARY_REQUEST` แปลว่าบอทกำลังขอสรุปท้าย session
ให้ตั้ง `response_kind: "summary"` แล้วทำตามหัวข้อ "Session และ Dashboard สรุปท้าย session"
ใน `SKILL.md` โดยใช้ประวัติ turn ทั้งหมดที่แนบมา (ไม่ใช่แค่คำถามสุดท้าย)

ปกติการสรุปควรมีกราฟ (`show_chart: true`) เพราะเป็น dashboard รวมของ session
แต่ถ้า turn ที่แนบมามี metric น้อยเกินจะปั้นกราฟที่มีความหมาย (เช่นถามค่าเดียว)
ให้ `show_chart: false` แล้วสรุปเป็นข้อความ — ดีกว่าโชว์กราฟแท่งเดียว

> การจำว่า session นี้ถามอะไรไปแล้วเป็นหน้าที่ของฝั่งบอท ตามที่ `SKILL.md` ระบุไว้
> บอทเก็บ state ใน SQLite แล้วแนบประวัติมาให้ในการเรียกครั้งนี้

## 5. เมื่อข้อมูลไม่พอ — ห้ามแต่งตัวเลข

ถ้าข้อมูลที่ต้องใช้ยังไม่มีใครอัปโหลดเข้าบอท:
- บอกตรง ๆ ว่าขาดส่วนไหน และใส่เหตุผลลง `data_gaps`
- ตอบเท่าที่ข้อมูลมีจริง
- ถ้าเว็บ/เดือนนั้นยังไม่มีไฟล์ที่เกี่ยวข้อง ให้บอกว่ายังไม่มีคนอัปโหลดไฟล์นั้น และควรอัปโหลดไฟล์ประเภทไหน

ถ้าไฟล์ benchmark ของเว็บที่ถูกถามไม่ได้แนบมาใน system prompt ให้บอกว่า
"ยังไม่มี benchmark ของเว็บนี้ในระบบ" แล้วตอบด้วยตัวเลขดิบ + trend โดยไม่ตัดสินสถานะ
— ดีกว่าเอา benchmark ของเว็บอื่นมาใช้ปน ซึ่ง `SKILL.md` ห้ามไว้
